# Лад — правила для агентів

## Джерела правди
- Канонічний обсяг: `docs/SPEC.md` (MVP v1.1).
- Формули й контрольні приклади: `docs/BUSINESS_RULES.md`.
- Порядок робіт і gate: `docs/IMPLEMENTATION_PLAN.md`.
- Фактичний стан: `docs/PROGRESS.md` — оновлювати лише після перевіреної роботи.
- SPEC v1.1 має пріоритет над старими суперечливими вимогами чи стартером.

## Продукт (стисло)
- Приватний застосунок для двох рівноправних учасників; українська UI; UAH; Europe/Kyiv.
- Одне оголошення = одна модель із багатьма кольорами **текстом**; без каталогу кольорів.
- Реклама — ручні платежі **на оголошенні**; маржа продажу = ціна − закупівля − прямі витрати **без** реклами.
- У v1 немає часток прибутку, виплат, боргів між учасниками.
- Повернення (BUSINESS_RULES §7) — **не погоджені**; не реалізовувати мовчки.

## Погоджені технічні рішення (основа)
- Вхід: email + пароль; відновлення через email; **без** публічної реєстрації.
- БД: окремий хмарний **тестовий** Supabase-проєкт (створювати/підключати лише за явним дозволом етапу).
- Стек: Next.js App Router, TypeScript, Tailwind, shadcn/ui, Supabase, Vercel.
- Тема: `#151619` / картки `#0b0c0d` / обводка `#24262b` / текст `#f4f4f5` `#9a9ca3` / акцент `#d4ff3a`.

## Дисципліна gate
- Gate 1 = лише основа (scaffold, оболонка, згодом Auth/RLS/workspace). Таблиці оголошень, реклами, продажів і календаря — на **наступних** gate, не «про запас».
- Одне невелике завдання → зміни → тести → ручна перевірка → `PROGRESS.md`.
- Не оголошувати gate готовим лише через успішний build.
- Не запускати старі `001_core.sql` / `002_sales.sql`; нова схема під v1.1.
- Не виконувати SQL, міграції, deploy чи зміни віддалених сервісів без окремого дозволу користувача.
- Секрети не в Git, docs, чат і логи. Для звичайних дій — user context + RLS, не `service_role` в UI-потоці.

## Безпека й цілісність (коли з’явиться БД)
- RLS обов’язковий; системні поля (`created_by`, timestamps, маржа, audit) не з клієнта.
- Фінансові завершення/корекції — лише контрольовані атомарні операції.
- Немає offline-черги запису у v1; конфлікт версії — явна помилка.

## UI
- Mobile-first, зручні натискання (≥44px де доречно), українські empty/loading/error/conflict.
- Не будувати Dashboard на 10 розділів у MVP.
